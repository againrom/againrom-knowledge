# Claim registry — TRIGGER (the runtime that evaluates a map's authored mission script)

Level 2 ledger. Index: [registry.md](registry.md) · spec: [`formats/trigger/format.md`](../formats/trigger/format.md). Legend: `✔ promoted` (also in the spec) · `● active` · `✖ retracted`. IDs are permanent.

This ledger is the **other half** of `claims/alm.md`'s type-7 rows. Those describe what a
map *stores*; these describe what `rom.exe` *does with it* — who evaluates the conditions,
on which clock, what can be tested, what a fired trigger can do, whether it fires again,
what survives a save, and what decides the mission is over. The map's bytes stay in
`claims/alm.md`; the clock and the session object are `claims/session.md`; the save
container is `claims/sav.md`.

Vocabulary note, because the engine's own words differ from the editor's: a condition is an
**instant**'s counterpart called a *check*, an action is an *instant*, and a trigger is a
*pattern* (`"Failed to create check %d %s"`, `"Failed to create instant %d %s"`,
`"Reference to suspicsious instant (%d) from pattern %d."`).

### TRIG-EVAL-001

`R0147` computes `server+0x04 % 16` (`L12296`…`L12297`, the same signed modulo `SESS-TICK-004` reads) and on phase **6** (`L00848` compares the phase with 6) calls `R0076` on the object `[L00004]` — the session — and the player list `[L00380]` as its one argument (`L12298`…`L00279`). `R0076` calls `R0433` (`L08519`), which evaluates **every** check, then `R0428` (`L01869`), which evaluates **every** pattern and runs the instants of those that pass, and only then walks players → groups → units. By `SESS-CLOCK-005` a sub-tick is `1000/R` ms with `R` defaulting to 16, so at the shipped default the trigger pass runs **once per 992 ms** while an actor's `vt+0x18` runs sixteen times in the same span. The dedicated-server loop `R0075` states the same cadence independently: one `R0076`, then a 16-iteration `R0193` loop, then `Sleep` to a 1000 ms period. There is **no event dispatch and no queue**: nothing anywhere in the machinery is called from a unit, a command or a message **`R0076` has two halves and a parallel lane read the other one the same day.** `AI-*`'s EXP-0082 reached this routine from the actor side and derived the **same** cadence from the **same** instructions — `L00279` after the signed modulo at `L00280`…`L00281` — so the once-per-full-tick period is stated by two independent readings and this clause is published High rather than Medium on that ground alone. Division of labour inside the routine: the two calls named here (`L08519`, `L01869`) run **before** the walk of players → groups → units that EXP-0082 reads at `L00282`, so **the whole authored script is evaluated before any AI group acts in the same tick**, and a consumer must preserve that order.

**Confidence.** High (the modulo, the phase constant, the two calls and the `ECX` are named instructions in two routines read whole; the wall-clock statement in `R0075` is a second, independent derivation of the same period)

**Amended.** The former table marked this claim contested without a separate note; the readings are those in the claim text.

### TRIG-STORE-002

`R1289` allocates `session+0xc2ac` = the **check list** (`new 0x1c`, vtable `L12299`), `session+0xc2b0` = the **instant array** (`new 0x14`, vtable `L12300`), `session+0xc2b4` = the **pattern list** (`new 0x1c`, vtable `L00574`), and zeroes two fixed arrays: `REP STOSD ECX=0x64` at `session+0xbd34` — **100 signed int result slots** — and `REP STOSD ECX=0xfa` at `session+0xbec4` — **1000 latch bytes** (`L12301`…`L12302`). The serializer `R0270` states both again as `Write` lengths `0x190` and `0x3e8` (`L08308`, `L12303`). **A check owns exactly one slot**, its own subscript, and writes it once per pass; an instant writes a slot only through opcodes 3 and 8. **The builder `R0067` bounds-checks neither array**, so a map with more than 100 conditions overwrites the latch array and one with more than 1000 triggers runs off the end of it. Corpus maxima over 38 maps: **64** conditions and **36** built patterns (`evidence/census.csv`)

**Confidence.** High (the two `REP STOSD` counts and the three allocations are named instructions in one constructor; the serializer's two lengths are an independent statement of the same two numbers; the absence of a bounds check is a read of the builder's own loops)

### TRIG-COND-003

`R0433` copies the 80-byte check record out of the list node (a 0x14-dword block copy at `L12304`), reads the opcode at `rec+0x04`, bounds it (opcode − 1 compared with 0x15, above jumping to `L12305`) and dispatches (`L12306`). Table re-read out of the PE through its own section table: 22 entries, and the two dwords past it decode as code. **Arms 11 and 13 point at `L12305`** — the loop's own continue label — so those opcodes are dispatched and write nothing, leaving the slot at its previous value. Arm by arm, with what each writes into its slot: `evidence/rom-vocabulary.md`. Three of them are not value tests at all: **18 writes no slot and increments the lose counter `session+0xb3b4`** when its unit is dead (`R1288`), **22 moves an object** it finds at a cell before answering (`R1616` → `R1055`), and **19 just copies another slot** (`R2052`), which is how a mission variable is read. A check whose opcode is `0x10002` is never dispatched: `R0067` gives it a slot and presets that slot to the node's `value[0]` (`L07782`) — **that is the engine's entire notion of a mission variable**

**Confidence.** High for the table, its extent, the dead arms and the three structural oddities (the bound is the routine's own `CMP`, the table was read out of the PE, and each arm was read at instruction level) / **Medium** for the *meaning* of arms 4, 9 and 20, whose fields (`unit+0x94`, `unit+0x158`'s sub-object, `actor+0x42`) are located and not interpreted

### TRIG-ACT-004

### TRIG-GROUP-005

Arm 6 calls `R0156(rec)`, which switches on `p0 − 1` and returns without acting for any value outside its ten cases. Implemented `p0`: **1, 2, 3, 4, 5, 10, 11, 14, 15, 17** (`evidence/rom-vocabulary.md`). The shipped catalog declares **eleven** signatures sharing opcode 6 with `Par0` `Const` literals `1 2 3 4 5 10 11 14 15 17 18` — so literal **18 is authorable and inert**. Shipped maps use nine of the eleven (135 nodes; `evidence/sub6.txt`), never 17 and never 18, so the inert form is not exercised by anything that ships. This is the mechanism behind `ALM-TRIG-045`'s "the literal that selects among the eleven signatures sharing opcode 6": the literal is a **runtime** subscript, not only an editor label

**Confidence.** High for the sub-dispatch and its ten cases (one routine read whole; the fall-through is the switch's own missing case) / High for the 11-vs-10 difference (the catalog is a shipped file this repo did not author and the literals were parsed from it, `evidence/sub6.txt`)

### TRIG-CMP-006

`R0428` reads a triple `(a, b, code)` from the pattern's condition list (`L12312`…`L12313`), bounds it (the code compared with 0x5, above jumping to `L12314`) and dispatches through the **6-entry** table at `L02136` (`L12315`). Each arm loads `session[0xbd34 + a*4]` and `session[0xbd34 + b*4]`, does one `CMP`, and takes one conditional jump: `JZ`, `JNZ`, `JG`, `JL`, `JGE`, `JLE` for codes 0..5 in table order. The accumulator starts at 1 (`L12316`), any failing arm zeroes it (`L12314`) and the loop leaves for the next pattern immediately (`L12317`, zero test), so the pairs are a **short-circuit AND** and there is no OR anywhere. This settles `ALM-TRIG-047`'s Unknown, which had the alphabet as a plausible reading only. Corpus, over the 550 bound pairs of the 38 shipped maps: codes 0/1/2/3/4/5 appear 276/38/27/96/7/105 times, and **one pair on `scn:111` carries `0xffffffff`** — a comparison that the `JA` sends to the false path on every pass (`evidence/bind.txt`)

**Confidence.** High (the table is 6 entries read out of the PE, each arm is two instructions, and the corpus contributes a value outside the alphabet whose behaviour the model predicts)

### TRIG-FIRE-007

The pattern object built by `R0067` carries the trigger's `+0xb4` at its own `+0x08` (the load of `+0xb4` at `L12318`) and the trigger's **position in the map's type-7 trigger array** at `+0x14` (`L12319`…`L12320`). In `R0428`: if `+0x08 != 0` **and** `byte[session + 0xbec4 + index] != 0`, the pattern is skipped entirely (`L12321`…`L12322`); otherwise the latch is cleared (`L12323`), the conditions are evaluated, and on success the latch is set to 1 (`L12324`). **So `+0xb4 = 1` means fire at most once per session and `+0xb4 = 0` means re-evaluate and re-fire every full tick** for as long as the conditions hold. Corpus: **387 of 421** triggers are one-shot, **34** repeat (`evidence/bind.txt`), and the 34 include every standalone map's single trigger, which is why `ALM-TRIG-047` saw `+0xb4 = 0` there and could not name it

**Confidence.** High (the flag's path from the file word to the gate is three named instructions in two routines, and the latch's clear/set pair brackets the evaluation)

### TRIG-SAVE-008

Its store arm writes, in order, `0x190` bytes from `session+0xbd34` (100 result slots), `0x3e8` bytes from `+0xbec4` (1000 fire-once latches), `0x30` from `+0x08`, `0x190` from `+0xa828`, `0x9cc` from `+0xa9bc` including the 50×50 diplomacy matrix, two bytes, one dword and outcome integers `+0xb3ac/+0xb3b0/+0xb3b4`; load mirrors it field for field. ### TRIG-BIND-010

`R0067` runs three passes over the map's own lists (`map+0x40` actions, `map+0x5c` checks, `map+0x78` triggers). A node is built only if every `Target_Group`/`Target_Player`/`Target_Unit`/`Target_Structure` parameter resolves; otherwise it logs `"Failed to create instant/check %d %s"`, consumes **no** slot and **no** array element. Node ids are mapped to subscripts through two `CMap<int,int>`s (`R2053`), so a trigger slot naming an id that was never built resolves to **slot 0** rather than to nothing. A trigger whose **first** condition pair's left id is zero is dropped whole before anything is built (`004e...`, the `if (trg+0x80 == 0)` arm) — **23 of the 421 shipped triggers** (`evidence/bind.txt`). Only the pairs with *both* ids non-zero become triples; the corpus has 550 such, 644 wholly empty and **0 half-empty**, which is `ALM-TRIG-047`'s pair structure seen from the consumer. Each of the four action slots is used only when non-zero; an id above **5000** additionally logs `"Reference to suspicsious instant (%d) from pattern %d."` (`L12325 CMP …,0x1388`), which no shipped map triggers. Whole-corpus re-check with `TRIG-REC-011`'s three `Target_Unit` bands honoured: **0 of 1304 buildable nodes would be rejected**, 0 unresolved unit/group/structure/player references (`evidence/resolve.csv`)

**Confidence.** High for the pass structure, the drop rule, the 5000 threshold and the `CMap` indirection (one routine read whole, every quoted test a named instruction) / High for the corpus figures (whole-corpus, 38/38, and the resolver's own three bands are what make the count exceptionless)

**Amended.** The unit clause of the corpus statement (0 unresolved unit references, exceptionless) holds for the three bands as a static count. A `Target_Unit` in the hero band is resolved from the roster at binding (`TRIG-HEROORD-075`, `TRIG-HEROBIND-077`), so whether a node naming one is built depends on the roster (`TRIG-HEROFAIL-078`); the 196 hero-band references of the published EN table are not covered by the exceptionless count. The slot-0 clause is narrowed (`retracted.md`): it holds for an action and for an unbuilt condition below opcode `0x10002`; a condition above `0x10002` is never built but keeps `map[id] = current register` (`L13841`, then `L13842` to `L13843`), so a pair naming it reads the next condition's register (`TRIG-BINDORDER-101`).

### TRIG-REC-011

`R0478` case 7 reads one 796-byte node in the order `0x40, 4, 4, 4, 0x28, 0x28, 0x280` into `+0x000, +0x040, +0x044, +0x318, +0x048, +0x070, +0x098` (`L12326`…`L12327`) — the file's **fourth** dword is stored **last**, so `ALM-TRIG-045`'s file framing is confirmed and the runtime record is a permutation of it, not a copy. Trigger records are read **verbatim**, 184 bytes each, into a typed array at `map+0x78` (the size 0xb8 pushed at `L02404`). The compiled records: an **instant is 72 bytes** — `+0x00` its own subscript, `+0x04` opcode, `+0x08..+0x2f` ten plain ints in *encounter* order, `+0x30` unit, `+0x34` group, `+0x38` player, `+0x3c` the second reference of whichever kind came second, `+0x40` a `short` item `= value + 0xe18`, `+0x44` structure; a **check is 80 bytes**, the same layout plus `+0x48`/`+0x4c`, zero-initialised by `R0506`; a **pattern is 24 bytes** — condition-triple list, instant-subscript list, the once flag, two unread dwords, the trigger's array index. **`Target_Unit` is three id spaces, not one**: `R0507` sends `value < 10001` to the map's own unit table, `10001..11000` to a hero ordinal (`R0508`, which returns 0 outright in multiplayer), and `> 11000` to a static name table at `L02135`; the two failure strings are `"Can't resolve unit %d."` and `"Can't resolve hero %d."`. Corpus: 196 of the shipped `Target_Unit` references are hero-band, 0 name-band

**Confidence.** High for the read order, the three sizes and the three bands (the loader's seven `Read` calls sum to exactly 796 and each is a named instruction; the resolver's two `CMP`s are its own; the record layouts are read from the builder's stores and the consumers' loads) / **Medium** for `+0x0c` and `+0x10` of the pattern record, which no read was found for

### TRIG-INI-012

`R0966` is a `CStdioFile` reader on the sub-object at `server+0x44`; it opens the path `modeRead\|typeText` (`0x4020`) and, on failure, destroys its locals and **returns 0 having done nothing** — and its one call site (`L07872`, in `R0512`) **discards the return value**, so a missing file produces no message, no fallback and no state. When present it is a sectioned `[Name]` file: each `[` line allocates a `0x1c` section object (`R2054`) filed under its name, every other non-`;` line is appended to the current section, and the load logs `"Mission description loaded from "`. The sections the engine looks for are its consumers' own literals: `Humans.Hero` with `Name`/`Bag.`/`Armor`/`Weapon`/`Shield`/`Item` (`R0907`), `Outposts` (`R0474`, `"Invalid outpost production!"`), `Patrol` and `StandGround` (`R0062`, with `R0163` parsing the path and reporting `"Patrol path in section [%s] not found"`), `Items` (`R0946`), and `Players`/`Mission`/`Monsters` (`R1575`). The section lookup `R2055` has **4 callers** and the line parser `R0475` **4 callers** (`EnumRefs callto:`, 0 orphan), and **none of the eight is in the trigger machinery** — `R0067`, `R0433`, `R0428` and `R0262` do not reach either. `EXP-0077`'s census stands: 0 `.ini` entries in 4 080 archive entries and no `World` directory on disk **Joined by `ITEM-SPAWN-013` the same day, from the other side of the same routine.** That row enumerates the makers of a sack and finds `R0946` — one of the four `R0475` callers named above — reading this file's `"Items"` section and dropping each entry as a sack at the coordinates it carries, so **map-authored loot is in the mission `.ini` and in no `.alm` record set at all**, and `R0945` is a fifth consumer of the same load. Two independent readings, both capped Medium on the section *semantics* for the same reason: no such file ships, so the per-entry shape is read and not matched.

**Confidence.** High for the absence behaviour and for the consumer set (the open, the failure return and the discarded call site are named instructions; both caller enumerations state their instrument and report 0 orphan) / **Medium** for the section *semantics*, which are read from literals and call sites rather than from a parsed example — **no such file exists to test against**

### TRIG-DROP-013

Action opcode `0x10002` never reaches the instant dispatch: `R0067` takes the node's `value[0]` and `value[1]` as **bytes** (byte loads of offsets 0x48 and 0x4c at `L12328` and `L12329`), packs them `(y << 8) \| x` and appends to a `CWordArray` at `this+0x28` where `this = server+0x44`, i.e. **`server+0x6c`**. `R0065` — the hero-placement path whose strings are `"Oops - player has no groups %-["`, `"Warning - no drop location in .alm - random used"` and `"Error - can't place hero from previous mission on map."` — reads that same array at `server+0x6c` (offset 0x6c added at `L12330`), unpacks `x = word & 0xff`, `y = word >> 8`, and **when `x * y == 0` substitutes a random cell for both coordinates** (`L12331`…`L12332`) and logs the warning. **⚠ Two clauses of this row are corrected by [EXP-0096] (`MISSION-DROP-002`, `retracted.md`).** The fallback is `R0861(0x46) + 0x1e` and `R0861(n)` is `(rand() * (n+1)) / 32768`, not a modulo — it is **inclusive of `n`**, so the range is **30..100**, not the 30..99 that `rand() % 0x46 + 0x1e` gives. And the array is not read at `[0]`: the index is `R0861(GetSize() - 1)`, a **uniform random pick**, with `player+0x60` consulted as a per-player override before the array is touched at all. Every shipped map carries exactly one such action (38 nodes over 38 maps, `evidence/vocab.txt`). Action `0x10003` is the builder's other special case and constructs an object from a group id and four parameters; opcode `0x10004`, which the catalog declares, matches neither test and is discarded (`TRIG-ACT-004`)

**Confidence.** High for the write, the read, the packing and the fallback (both ends are named instructions in two routines read independently, and `0x44 + 0x28 = 0x6c` is the check that could have failed) / **Unknown** what `0x10003` builds — the constructor was located, not read

**Amended.** The fallback range and the array read corrected by EXP-0096.

### TRIG-DIST-014

`TRIG-COND-003` published three arms as "computes a distance" without naming the metric; there are **five**, and the metric is one routine. `R0162(x1,y1,x2,y2)` masks each argument to a byte, subtracts, takes each difference's absolute value with the branchless `CDQ`/`XOR`/`SUB` idiom (`L12333`…`L12334`, `L12335`…`L12336`) and returns `max(\|dx\|,\|dy\|)` as its return value — the compare at `L12337`, the below-or-equal jump to `L12338` at `L12339` and the replacing move at `L12340`, then a return popping 0x10 argument bytes.
