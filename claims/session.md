# Claim registry — SESSION (the game's own lifecycle: object, phase, clock, map load, mission end)

Level 2 ledger. Index: [registry.md](registry.md) · spec: [`formats/session/format.md`](../formats/session/format.md). Legend: `✔ promoted` (also in the spec) · `● active` · `✖ retracted`. IDs are permanent.

This ledger covers the machine the owner named as
`newgame → chargen → loadmap → playing → finish mission` and `city → pick mission → go`: which
object holds a session, what phase it is in, **what advances the simulation's counters and how
fast**, how a map becomes a session, and what happens when a mission ends. It is not a file
format. The map's own bytes are `claims/alm.md`; the actors it spawns are `claims/unit.md` and
`claims/hero.md`; the shop the town screen opens is `claims/shop.md`.

`SESS-CLOCK-005` says how fast the sub-tick runs; `SESS-PACE-018`
([EXP-0093](../experiments/EXP-0093-move-rate/)) says **which loop issues it**, that the same
iteration issues the `0x401` presentation tick `ANIM-CLOCK-001` names, and which two of the idle
handler's four arms let the two diverge.

### SESS-DEFEAT-064

**Frontend phase, local authority, map mode and participant state are separate predicates.** Five callers of allocator `R1304` pass 2 for new campaign `L07363` and campaign save load `L09302` (frontend phase `+0x6bc=2`), 0 for the two phase-3 authority starts `L09303/L09304`, and 1 for phase-1 host start `L09305`. Initializer `R0119` writes `server+0x0c=(arg<2)` and `+0x08=(arg>0)`; this is **not immutable**. ALM loader `R0128` loads the GLOBAL server pointer and overwrites `+0x0c=(map+0xd4>1)` at `L02087..L02089`, plus inverse flag `+0x120`. The field is type-0 payload `+0x70` (`ALM-MODE-070`). Fresh census: 28 EN and 28 RU campaign maps have value 1; all 10 EN loose maps and 5 of 6 RU loose maps exceed 1, but RU Horror has 1. Therefore campaign paths exclude automatic mode-nonzero recovery, while arbitrary loose-map/transport membership alone does not prove it. Save-load deserialization `R0414` does not restore this dword. Participant `+0x3e` is set by join `R0910`; `+0x3f` is set by mission entry `R0131`, cleared by session opcode 5 and disconnect `L09306`; neither is the mode dword. The second initializer caller `R1662` takes an argument; no incoming direct or stored-address candidate was found, so runtime use is Unknown.

**Confidence.** High for all observed mode producers, phase callsites, participant writes and the loose-map counterexample; corpus alone is Medium, joined to the independently read load predicate. Wholesale object mutation and arbitrary external entry are not excluded

**Status.** ● active

**Evidence.** [EXP-0274](../experiments/EXP-0274-defeat-modes/)

### SESS-DEFEAT-065

**Campaign outcome panels block frontend stepping without clearing the server run flag; network branches are separate.** `R0560` first routes phase 3 with authority to `R0455`; in a map screen it routes no-authority clients to `R0640`, then skips local simulation only when phase 2 and screen `+0x3dc & 0x4008 != 0`; otherwise `R0454` or `R0260` calls `R0147`. Both outcome panels call `R0361`, which sets bit 8 for these panel identities. Stepper `R0147` requires run dword `server+0x2c != 0` and calls `R1576` at subclock modulo 16 equal to 15; its other caller is bootstrap `R0099`. The reporter chain is `R1576 -> R1663 -> R0132`. A second `R1576` caller exists in loop `R0075`, reached by thread callback `R0261` whose address is pushed in `R0456`; no incoming direct or stored-address candidate for the launcher was found. Thus that loop is not assumed to run beside campaign idle. Third placement-helper caller `R1290` is an optional watchdog behind `server+0x148 != 0`, full clock modulo 5, empty selected-character result and `server+0x13c != 0`; its countdown-zero branch calls placement, not the XP repair or failure reporter. Constructor defaults both watchdog flags to zero; deserialization restores them.

**Confidence.** High for enumerated caller sets, idle mode ordering, panel bit and separation of watchdog/repair. Runtime thread use, nondefault watchdog reachability, packet backlog and observed pause/recovery duration remain Unknown

**Status.** ● active

**Evidence.** [EXP-0274](../experiments/EXP-0274-defeat-modes/)

### SESS-INPUT-037

**The mission input precedence is a concrete tree, not overlapping polling.** Root `campaign+0xcc` owns map then right column; the right column owns minimap, command panel, character panel and filler in that order, and the measured inventory-open route appends the inventory grid to the map view (MENU-088). A capture object receives any physical mouse event first; otherwise the first child containing the point receives it and traversal stops even if it returns zero. A focused child receives keyboard first and suppresses parent/map shortcuts when it consumes them. This is why the map never receives clicks inside the 160-pixel column, a popup's Esc closes the popup, and the text-entry child suppresses mission shortcuts. Inventory-grid left-up with live content and `session+0x3cc` selected routes the hit through grid vslots `+0x88` then `+0xa4` and emits item transfer `0x22/0x32`; a `-1` hit uses the destination's merge/append fallback rather than becoming a no-op. The grid's other mouse edges are separate: left-down scrolls one position through edge strips, left-button move builds item/money drag state but no order, and right down/up/double-click are consumed no-ops. Inventory-grid double-click can attach the always-created Drop Gold dialog at `campaign+0x10c`; the modal then takes focus, Enter/Esc map to action/cancel, and its child buttons act on inside left-up. Neither command panel nor minimap sets the engine capture object; the map sets it only for a right-button pan. A left marquee instead calls OS `ClipCursor` on down with a computed map rectangle, but only while `[L00210]` is zero. A normal up calls `ClipCursor` with `session+0x6c0`, updates the hit and selects/orders only while that global is nonzero; an inactive up skips those steps, although its later selected-item arm remains reachable. Neither left edge sets or clears engine capture

**Confidence.** High (construction/append tree, base dispatcher, complete inventory-grid and dialog/button physical vtables, focus helpers, both marquee-global gates, post-gate item branch and both `ClipCursor` arguments read end to end)

**Status.** ● active (partially retracted)

**Evidence.** [EXP-0190](../experiments/EXP-0190-combat-controls/), [EXP-0476](../experiments/EXP-0476-backspace-descendants/)

**Amended.** The character-panel inventory-grid parent clause is partially retracted. MENU-088 reads the map-view call and append at L06488. Other precedence, physical handlers, capture and marquee clauses stand.

### SESS-OBJ-001

**The session object is the MFC main frame window, and every `campaign+…` displacement published anywhere in this tree is a field of it.** `InitInstance` (`R0326`) allocates `0x6d0` bytes (the size 0x6d0 is pushed at `L09307` and the routine at `R0747` is called at `L09308`), constructs it with `R0341` (`L09309`) — which installs the vtable at `L09310` — and stores the result into the app's `m_pMainWnd` **two instructions later** (`L09311` stores the result into the 32-bit field at offset 0x1c of the object returned by `AfxGetApp()`), then re-loads it and publishes its `HWND` to `[L06446]` (`L09312`). Every consumer image-wide reaches it the same way — `R0347` (`AfxGetThread`) then an indirect call through the 32-bit slot at offset 0x7c of the thread object's function table — which is the idiom `UNIT-PANEL-010` already quotes for its `+0x6bc` guard. So `UNIT-GATE-012`'s "campaign object" and `SHOP-MISSION-018`'s "campaignScreen" are the same object, and `campaign+0x65c` (`L09313` stores the 32-bit constant 1 into the field at offset 0x65c of the main-window object) is a field of the main window. It is **not** the server singleton: that is the separate `0x174`-byte object at `[L00285]`, allocated by `R1304` (`UNIT-GATE-012`)

**Confidence.** High (the allocation size, the constructor, the `m_pMainWnd` store and the `0x65c` default are four named instructions in one routine, and the getter idiom is the same two instructions at every consumer; the size discriminates against the server object, which is `0x174`)

**Status.** ● active

**Evidence.** [EXP-0076](../experiments/EXP-0076-session-lifecycle/)

### SESS-PHASE-002

**There is an explicit phase field, `campaign+0x6bc`, and the image does *not* state its value set — it is the union of a complete writer enumeration.** `EnumRefs disp:6bc`, whole image: **71 hits, 39 owners, 0 in orphan/undisassembled code**. Nine of them are stores: `L09314` and `L09315` in the message handler `R0701`, `L09316` in `R1382`, `L06706` in `R1284`, `L09317` in `R1323`, `L09318` in `R1664`, `L09319`, `L09320`, `L09321`. The immediates are `0`, `1`, `2`, `3`; the two register stores carry values from the same set. **Every one of the 62 reads is an equality test** against 0, 1, 2 or 3 — there is no jump table and no range test on this field anywhere in the image, which is exactly what `UNIT-GATE-012` had for `server+0x84` and this does not. Naming by the writers' own string operands: `R1382` sets **2** and is the campaign-start routine (it is the one that parses `-female`/`-mage`); `R1284` sets 2 on the load path; `R1665`/`R1666` set **3**; `R1667` sets **1**; `R1323` sets **0** and is the `-waitforever` shutdown arm. `campaign+0x6bc == 2` is the guard `UNIT-PANEL-010` already reads as "in a campaign session"

**Confidence.** **Medium** for the value set (a complete writer enumeration with a stated instrument, which is strictly weaker than a range test; a value arriving through a `memcpy` or a whole-object copy carries no displacement and would not appear) / High for the location and the writer set / **Medium** for the phase *names*

**Status.** ● active

**Evidence.** [EXP-0076](../experiments/EXP-0076-session-lifecycle/)

### SESS-SCREEN-003

**`campaign+0x3dc` is a second, independent state word and it is a bitmask, not a phase.** It is read-modify-written (at `L09322` the low byte is masked with 0xfe to leave the map screen, at `L09323` bit 0x8 is set in the byte holding bits 8 to 15 of the working value, and at `L09240` the 32-bit field at offset 0x3dc is masked with 0xffffdfff) and tested by mask (against 0x1, 0x2 and 0x8, and by a 32-bit memory-operand test against 0x226 at `L03383` and 0x627 at `L03384`). **Bit 0 is "a map session owns the frame"**: `R1149` sets the whole word to `1` after attaching the map view and its children (`L06481`) and `R1660` clears bit 0 while detaching them and posting `0x403` (the low-byte mask with 0xfe at `L09322`); the idle handler runs a **simulation tick** only on the set branch (`L06902` tests bit 0 and branches on zero) and on the clear branch merely repaints. `R1322` zeroes the word outright. This is the same word `SHOP-TOWN-023` reads as the campaign's **home state** at value `0` — no map, hence the town screen — and the two readings agree: 0 means no session on screen. Bits 3 and 14 together (a test against the mask 0x4008 at `L03333`) suppress the tick while the phase is 2

**Confidence.** High for the shape and for bit 0 (the set/clear pair and the idle handler's branch are named instructions, and `SHOP-TOWN-023` reads the same field from the other side) / **Unknown** for bits 1, 2, 9, 10 and 13 individually — they are exercised only through composite masks

**Status.** ● active

**Evidence.** [EXP-0076](../experiments/EXP-0076-session-lifecycle/)

### SESS-TICK-004

**There are two counters on the server singleton, not one, and the standing Unknown of `HERO-REGEN-021`, `HERO-DEATH-026` and `SHOP-LIFE-014` is closed by the pair.** `server+0x04` is the **sub-tick** counter and is incremented by exactly one instruction sequence image-wide, at the head of `R0193`: `L09324` loads the 32-bit value at offset 0x4 of the object, `L04051` increments it by one and `L05394` stores it back at the same offset. `server+0x00` is the **full-tick** counter and is incremented in `R0147` at `L04049`…`L04050`, **gated on `server+0x04 % 16 == 15`** (`L09325`…`L09326`, a signed modulo by 16 written out as sign extension, exclusive-or, subtraction, a mask with 0xf, exclusive-or and subtraction). So **one full tick is exactly 16 sub-ticks**, and `SHOP-LIFE-014`'s divisor `0xb4` counts full ticks, `HERO-REGEN-021`'s `% 4` filter selects one full tick in four, `HERO-DEATH-026`'s low-bit filter one in two. Nothing advances either counter when `server+0x2c == 0` — `R0147` returns at its first test (`L02033`)

**Confidence.** High (both increments are named instructions in routines read whole; the 16:1 relation is the gate's own comparison of the remainder with 0xf; the two counters are told apart by `R0547` reading `+0x04` while the three cited claims read `+0x00`) / **Medium** that these are the *only* increments — the instrument is a read of both routines plus `callto:` closure on `R0147` and `R0193`, and an `ADD` through a register at another site would carry no displacement and no immediate to sweep for

**Status.** ● active

**Evidence.** [EXP-0076](../experiments/EXP-0076-session-lifecycle/)

### SESS-CLOCK-005

**The sub-tick is paced against `timeGetTime` and the image states the whole rate ladder, so "180 ticks" finally has a unit.** `R0559(index)` clamps its argument to `[0, 8]` (`L02618`, `L09327`…`L02619`), stores it at `campaign+0x3f4` and dispatches through a **9-entry** jump table at `L02620` whose arms load `R ∈ {8, 10, 12, 14, 16, 20, 24, 28, 32}`, then computes `campaign+0x3f0 = 1000 / R` (`L02621` loads the constant 0x3e8 and `L02622` divides it by R, signed) — **milliseconds per sub-tick** — and resets the phase and the epoch. The **default is index 4**, set by the constructor: `L09328` stores the 32-bit constant 4 at offset 0x3f4 of the object under construction. The paced loop `R0454` fires a sub-tick only when `(phase + 1) × campaign+0x3f0 + campaign+0x3ec <= timeGetTime()` (`L09329`…`L02625`) and re-epochs every 16 (`L02632`). **At the shipped default a sub-tick is 62 ms and a full tick is 992 ms**, so `SHOP-LIFE-014`'s 180 is ≈ 178.6 s; the whole ladder is `evidence/tick-rate.csv`. Keys `[GameOptions] Speed` in the save (`R0098`, `L09330`) carries the index. **Two bounds a consumer must carry:** the loop is a *deadline* loop with a catch-up branch (`L02630 JBE`), so the rate is a ceiling, not a guarantee; and the arm taken when `campaign+0x40c != 0` (`R0260`) has **no deadline test at all** and increments the phase **without** the mask with 0xf, so under it the sub-tick runs once per idle callback

**Confidence.** High (the clamp, the nine arms, the division, the default and both loops are named instructions; the jump table was re-read out of the PE through its own section table rather than off a listing)

**Status.** ● active
